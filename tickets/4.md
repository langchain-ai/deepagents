# Ticket 4: exclude OAuth callbacks from retrieved Slack context

- Status: open
- Priority: P2
- Component: `deepagents-talon`
- Planned PR: `fix(talon): exclude OAuth callbacks from Slack thread context`
- Review finding: 6

## Problem

The live-message path intercepts OAuth callback URLs before agent invocation, but Slack thread retrieval can supply those same messages again. `SlackChannel._process_message` filters retrieved replies by sender, then places their text into `slack_thread_context`. The host includes that context in the next agent input without applying callback filtering.

A callback pasted by an authorized operator can therefore reach the model, checkpoints, archives, or tracing through a later message. The confirmed impact is disclosure of callback code/state; account takeover was not demonstrated.

## Reproduction

Using the recording Slack gateway and host:

1. Deliver an operator's thread message containing `http://localhost:3000/callback?code=TEST_SECRET&state=TEST_STATE`.
2. Verify the host intercepts it and does not invoke the agent.
3. Return that earlier message from the gateway's thread-context retrieval.
4. Deliver an ordinary follow-up in the same thread.
5. Observe `TEST_SECRET` in the resulting `AgentRequest.text`.

This was reproduced without real credentials, model calls, or Slack access.

## Implementation scope

- Exclude callback credentials from retrieved thread content before it enters model-facing metadata or text.
- Apply filtering before truncation or concatenation can obscure a callback's recognizable structure.
- Reuse callback recognition semantics where appropriate, while accounting for Slack link encoding, bot mentions, and surrounding prose in historical messages. Recognition for exclusion must not authorize or complete a login.
- Preserve ordinary context and existing sender filtering. Maintain the current live-flow checks for exact redirect URI, sender, conversation, invocation, and expiry.
- Avoid logging raw callback text while filtering it. Use a bounded neutral omission marker only if it helps the agent understand missing context.

## Acceptance criteria

- [ ] A callback intercepted live remains excluded when retrieved on a later turn, including when no authorization is pending.
- [ ] Fake code/state sentinels are absent from `AgentRequest.text`, model content, and retrieved-context metadata.
- [ ] Slack-encoded links, bot-prefixed callback messages, supported loopback variants, and callbacks near truncation boundaries are covered.
- [ ] Ordinary URLs, neighboring thread messages, and sender restrictions remain intact.
- [ ] Live callback completion and rejection behavior remains unchanged.
- [ ] Network-free host/runtime coverage verifies excluded credentials do not enter persisted conversation messages or model-facing callbacks.
