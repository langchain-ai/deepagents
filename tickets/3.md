# Ticket 3: authorize WhatsApp media before downloading

- Status: open
- Priority: P1
- Component: `deepagents-talon`
- Planned PR: `fix(talon): authorize WhatsApp media before downloading`
- Review finding: 5

## Problem

The WhatsApp bridge calls `downloadMessageMedia` and writes attachments to disk before the Python adapter applies `_allows_whatsapp_message`. Under default `self` exposure, a stranger's attachment therefore consumes download, memory, and disk resources even though the message cannot trigger the agent.

The bridge also starts message preparations concurrently and keeps an unbounded queue. A per-file size cap does not bound aggregate downloads, concurrent memory use, or stored bytes. Current media retention cleanup runs at startup, so it does not provide a runtime storage bound.

## Reproduction

A local harness loaded the real bridge with mocked WhatsApp, network, and filesystem dependencies. With `self` exposure configured, enqueueing a non-self sender's attachment still invoked the download helper and filesystem write before Python could reject the message. No live account or real attachment was used.

## Implementation scope

- Decide whether a message is admitted from a lightweight envelope before Talon explicitly downloads or persists its media.
- Keep Python exposure policy authoritative, or establish a shared contract that cannot drift from it. A two-stage bridge flow that requests media only after Python admission is one option.
- Preserve current self-chat rules, configured operator identities, chat allowlists, mention-pattern behavior, and explicitly enabled open exposure. Reject by default when admission cannot be determined.
- Bind any deferred media request to the admitted message and conversation. Retain the bridge's bearer-token and loopback protections.
- Bound pending envelopes, concurrent media preparation, and retained media bytes. Define overload behavior and clean up partial, rejected, or abandoned downloads during normal operation.
- Preserve per-file limits and prevent oversized or unknown-size media from causing unbounded concurrent buffering.
- Coordinate sequencing and cancellation with [ticket 2](2.md); admission must happen before preparation without allowing older media to restart cancelled work.

## Acceptance criteria

- [ ] A sender rejected by exposure policy causes no Talon-initiated media download or attachment write.
- [ ] Authorized self-chat, operator, allowlist, and open-exposure messages retain their existing behavior.
- [ ] Approval reactions and bot-echo suppression continue working.
- [ ] Queue, concurrency, and aggregate-storage limits hold under a burst of messages.
- [ ] Overload, cancellation, and failed downloads release capacity and remove partial files.
- [ ] Missing or invalid admission information cannot authorize a deferred download.
- [ ] Tests exercise the bridge and Python admission boundary with inert media and mocked transports.
